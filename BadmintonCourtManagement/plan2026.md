## Definition of Done — Feature #10 (Inventory Management)

### Database
- `inventory_item`, `purchase_lot`, `stock_movement` tables created via Liquibase changesets.
- `item_id` FK added to `shuttle_ball` and `service`; backfill creates items for active catalog names.
- Monetary columns in new tables use `BIGDECIMAL`.

### Backend
- All endpoints under `/api/inventory/**` return `403` for non-`rootuser` (same pattern as `ProductsController`).
- `POST /api/inventory/purchases` records a `purchase_lot` + `PURCHASE_IN` movement transactionally.
- Stock on hand = `SUM(stock_movement.quantity_delta)` per item; never stored inconsistently.
- Game FINISH writes `GAME_CONSUMPTION` movements per `GameShuttleMap`; low-stock warning on game START.
- Retail sale of stockable goods writes `RETAIL_SALE` on player checkout (ServiceDTO carries `itemId` + `quantity`).
- `POST /api/inventory/adjustments` records `ADJUSTMENT` with mandatory reason.
- Margin = `retail_price − weighted avg unit_cost`, exposed on items endpoint.
- Protected pricing rows (`costInPerson`, `rentByTime`) never become stockable.
- All mutations transactional — no partial stock state (project convention).

### Frontend
- Inventory page (rootuser-gated nav): stock on hand, avg cost, retail, margin, low-stock badge.
- Purchase intake form.
- Per-item ledger view and adjustment dialog with reason.
- Shuttle selector + service picker show remaining stock; out-of-stock items blocked.

### Verification
- Unit tests cover movement math (intake, consumption, sale, adjustment, avg-cost margin).
